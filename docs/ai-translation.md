# AI 长句翻译（Windows 0.9.4 修复版）

在「设置 → AI 辅助」手动开启 **AI 长句翻译**，选择目标语言。默认关闭；AI 联想的原开关独立保留。API 提供商、模型、Token 和接口地址共用现有配置。

悬浮工具栏的简繁按钮依次循环「简 → 繁 → 简译 → 繁译 → 简」。内部仍然是字符集与翻译开关两个状态。原简繁快捷键只改变字符集；新翻译快捷键在设置中填写，例如 `Ctrl+Alt+T` 或 `Alt+F8`，留空不注册。格式支持 Ctrl / Alt / Shift / Win 与字母、数字、F1–F24 的组合，不能占用原来的 `Ctrl+Shift+F`；已被其他应用占用的组合会报告设置保存失败。

## 输入与上屏

只有当前第一条已经解析出的中文候选参与翻译。原始拼音、英文输入、表情、日期及候选子页面不会作为中文源文本发送给翻译服务。停键约 650 ms 后才对缓存未命中的内容请求 AI，缓存命中不等待这个延迟。任务、数据库查询与网络请求在独立后台线程执行，译文回到现有候选队列时验证输入会话、候选代次、目标语言和字符集，旧结果不会覆盖新输入。

第一条中文候选旁显示完整译文，沿用原生候选列表的换行和测量。普通 Space / 数字键仍提交中文。高亮第一条候选时 `Ctrl+Enter` 直接提交完整译文，译文内的分号不会被拆成多个词义，中文目标语言也不会再次被输入法的源字符集转换。

联网失败、超时、HTTP 错误、无效 JSON 或截断响应只丢弃译文，中文输入继续工作。输出预算为 4096 token，`gpt-6-luna` 使用 `max_completion_tokens` 和 `reasoning_effort: none`。已有 AI 联想和连接测试仍保留 2048 的 luna 预算；兼容提供商继续使用 `max_tokens`。

## 本地缓存

数据库位于输入法数据目录下的 `ai-translations.db`，沿用产品原有 SQLite 依赖，未引入外部数据库或 Google API。第一次翻译或清空缓存时创建。

表 `translations` 保存原始中文、目标语言、源字符集、必要上下文、译文、UTC 更新时间、来源 `ai`、提供商和模型。复合主键为 `(source_text, target_language, source_character_set, context_key)`；提供商和模型是记录元数据，换模型不会丢弃同语言的既有译文。结构保留 `origin` 字段以方便以后支持用户编辑，以及导出、导入或同步。

明确的名词和完整句子按源内容复用，不因上屏历史增长而重复请求。单字、常见多义短语及含「这个 / 那个 / 他 / 她 / 它」等指代的短句保留上下文键；上下文不同可能需要新译文。此规则是本地启发式，不额外调用 AI 判断歧义。

「清空 AI 翻译缓存」删除译文记录并递增数据库纪元。清库前已经发出的请求不能重新写入旧结果；当前屏幕已经显示的译文可以保留到本次组合结束，下一次输入重新查询缓存。SQLite WAL 与事务支持 Server / Settings 两个进程并发访问。

## 实际测试

1. 先关闭「AI 联想」，仅开启「AI 长句翻译」，目标语言选择 English。这样统计请求时不会混入中文 AI 联想的调用。
2. 输入 `nijintianshangbanlema`，确认第一候选是想表达的中文。停键等待译文；Space 上屏中文，再输入同一句，译文应从缓存快速出现。断网后重复这句仍能显示缓存译文。
3. 高亮第一候选按 `Ctrl+Enter`，应上屏完整英文。再测试较长中文句子，确认译文换行且中文候选不等待网络。
4. 改选 Filipino / Tagalog、Japanese、Korean、Simplified Chinese、Traditional Chinese。不同目标语言分开缓存；测试繁译时提交简体中文译文，仍应保持设置指定的目标文字。
5. 点击状态栏循环四种状态；配置翻译热键后只切翻译，再使用原简繁热键只切字符集。
6. 关闭 AI 长句翻译，输入新句子，不应出现 AI 翻译请求。保持 AI 联想关闭时也不会有中文联想的 API 请求。
7. 清空缓存，下一次输入之前缓存过的句子应重新翻译。无网时输入尚未缓存的句子，中文候选和 Space / 数字上屏应正常。

## 开发验证

新增独立 `ai_translation` CTest：持久化及重启命中、OFF / 拼音零调用、目标语言与字符集隔离、歧义上下文、明确名词和问题的缓存复用、慢请求非阻塞、取消、失败不入库、清库与进行中请求的竞争、四种状态及自定义快捷键。

配置模板迁移测试检查新开关独立且保留已有凭证；设置页测试检查开关、语言与清库只写对应翻译字段。已有 OpenAI 参数兼容矩阵加入 4096 输出预算。

`ai_translation_live_probe` 是手动联网验证工具，不加入自动 CTest。只读现有配置、只把凭证保留在内存，对合成中文分别验证英文 / Tagalog，以及缓存复用；控制台仅输出成功状态和请求次数，不输出凭证或模型响应。测试使用临时数据库并在结束时清理。

本地编译与测试使用原 `server/build-release`，真实词库按 `product-lock.json` 的 SHA256 校验并通过环境变量隔离，绝不把单元测试指向用户正式数据目录。
